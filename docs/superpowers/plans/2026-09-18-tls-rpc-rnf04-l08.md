# RNF04 / L-08 — TLS no RPC do Backend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fechar RNF04 — "TLS 1.3 em todas as comunicações", classificado **Crítico** na matriz de capacidades do PRD — pondo o RPC do backend atrás do Traefik com HTTPS e **removendo** a porta 8080 em texto claro, que hoje é o único caminho que os apps usam.

**Architecture:** O Traefik já está na stack, mas **não roteia o MQTT** (medido: o broker publica a 8883 direto, sem label nenhuma) e **não termina TLS nenhum e não tem rota declarada para o backend**: a porta 8080 é publicada direto no host (`docker-compose.yml:129-130`), então os apps falam HTTP puro sem passar por ele. Este plano adiciona o entrypoint `websecure` (:443) com um certificado de desenvolvimento, um router explícito para o serviço `serverpod` e **remove a publicação de 8080** — sem isso o TLS seria decorativo, porque o caminho sem criptografia continuaria aberto. A CA de desenvolvimento é **uma nova, própria do RPC**, e não a do Mosquitto: a do broker é consumida por três lugares que hoje funcionam e são validados (o próprio broker, o asset do app ACS e a conexão de saída do backend), e reaproveitá-la obrigaria a mexer no `infra/docker/mosquitto/init.sh` e nos caminhos de `runtime/` — risco desnecessário para um requisito que é aditivo. Unificar as duas CAs depois é uma limpeza possível, e fica registrada.

**Tech Stack:** Docker Compose, Traefik **v2.11** (o plano dizia v2.10 — ver a nota abaixo), `openssl` (já usado por `infra/docker/mosquitto/init.sh`), Dart/Serverpod (`backend/sinalacs_server/config/development.yaml`), Flutter (`apps/acs`, `apps/patient`) com `SecurityContext.setTrustedCertificatesBytes` (o mesmo recurso que o app ACS já usa para o MQTT).

**Spec:** `spec/PRD_system.md` linhas 155 (RNF04 na matriz, criticidade **Crítico**, dependência "Traefik, cert-manager"), 97 (o diagnóstico: "O RPC do backend é HTTP puro na 8080, sem TLS, inclusive do emulador"), 645-667 (§4.2 Segurança por Design); `spec/stack.md:19` (Traefik como *Reverse Proxy/Edge Gateway*); `spec/validation_report.md` linhas 266-267 (**L-08**). Nota: não existe `spec/` para o certificado de desenvolvimento — o padrão vem de `infra/docker/mosquitto/init.sh` e de `scripts/dev/sync_dev_ca.sh`.

## Global Constraints

- **A porta 8080 em texto claro é REMOVIDA, não restringida.** Enquanto ela existir no host, o RNF04 não está atendido: o requisito é "TLS em **todas** as comunicações", e um caminho sem criptografia ao lado de um com criptografia é o caminho que alguém vai usar. Isso implica atualizar todo o ferramental que aponta para `http://…:8080/` (Task 5) — é a maior parte do trabalho real deste plano.
- **A CA do Mosquitto não é tocada.** `infra/docker/mosquitto/init.sh`, `infra/docker/mosquitto/runtime/` e `apps/acs/assets/certs/dev_ca.crt` continuam exatamente como estão. O RPC ganha CA e certificado próprios, em `infra/docker/traefik/`.
- **Certificado de desenvolvimento, não de produção.** O PRD cita `cert-manager` como dependência de RNF04; emitir certificado confiável em produção é decisão de infraestrutura (domínio, DNS, ACME) que este repositório não tem como tomar. O que este plano entrega é o **caminho cifrado funcionando ponta a ponta em desenvolvimento**, com a URL e a terminação já no lugar para receber um certificado real. Nada de ACME/Let's Encrypt aqui: sem domínio real, o desafio não passa.
- **Só TLS 1.3 nos entrypoints.** O PRD pede TLS 1.3 nominalmente; o Traefik aceita configurar `minVersion`. Deixe `VersionTLS13` como mínimo no `websecure`, para que o requisito seja verificável e não apenas "tem alguma criptografia".
- **A verificação de hostname permanece ligada nos apps.** O app ACS já faz isso para o MQTT e herdou a lição: `Serverpod SecurityContext` sem certificado confiável deve **falhar**, nunca cair para "aceita qualquer certificado". Proibido usar `badCertificateCallback => true`.
- Comentários, mensagens e nomes de arquivo em português, como o resto de `infra/` e `scripts/`.
- `infra/docker/traefik/runtime/` (certificados gerados) entra no `.gitignore`; o script gerador e o arquivo de configuração dinâmica **são versionados**.

## Task 1: CA de desenvolvimento do RPC e certificado do servidor

**Files:**
- Create: `infra/docker/traefik/init.sh`
- Create: `infra/docker/traefik/dynamic/tls.yaml`
- Modify: `.gitignore`

**Interfaces:**
- Produces: `infra/docker/traefik/runtime/certs/{ca.crt,server.crt,server.key}` e o arquivo de configuração dinâmica que o Traefik carrega. (O serviço de compose `traefik-init` que executa este script é declarado na **Task 2** — esta task entrega o script, não o serviço.)

O `init.sh` segue a forma do `infra/docker/mosquitto/init.sh` — que é o precedente do repositório para "certificado de desenvolvimento gerado no boot, nunca versionado" —, inclusive a variável de SAN extra para validar em aparelho físico na LAN.

- [ ] **Step 1: Escrever o gerador de certificados**

Cria `infra/docker/traefik/init.sh`:

```sh
#!/bin/sh
#
# Gera a CA de desenvolvimento do RPC e o certificado do servidor que o
# Traefik apresenta em :443 (RNF04).
#
# CA PRÓPRIA, separada da do Mosquitto: aquela é consumida pelo broker, pelo
# asset do app ACS e pela conexão de saída do backend — três coisas que hoje
# funcionam e são validadas. Unificar as duas é uma limpeza possível, mas
# obrigaria a mexer no init.sh do broker e nos caminhos de runtime/ dele; o
# ganho não paga o risco num requisito que é aditivo.
#
# A CA é PRESERVADA entre subidas e só a folha é regerada — e isso **não é uma
# escolha nova**: é o que o `mosquitto/init.sh` já faz, com guardas `needs_ca` e
# `checkend`. Regerar a CA a cada subida invalidaria em silêncio o
# `dev_rpc_ca.crt` já copiado para o asset dos apps, e o app só falharia no TLS
# depois de um restart, longe da causa. Não é versionado (o `.gitignore` cobre
# `runtime/`), mas é regenerável: apagar o diretório é o caminho de recuperação.
tls:
  certificates:
    - certFile: /certs/server.crt
      keyFile: /certs/server.key
  stores:
    default:
      # Sem isto, uma requisição cujo SNI não case com nenhum certificado
      # recebe o certificado default do Traefik (auto-assinado por ele), e o
      # app falharia com erro de confiança em vez de chegar ao servidor.
      defaultCertificate:
        certFile: /certs/server.crt
        keyFile: /certs/server.key
  options:
    default:
      # RNF04 pede TLS 1.3 nominalmente. Declarar o mínimo torna o requisito
      # verificável (`openssl s_client -tls1_2` precisa FALHAR), em vez de
      # "tem alguma criptografia".
      minVersion: VersionTLS13
```

- [ ] **Step 1: Acrescentar o serviço gerador e reconfigurar o Traefik**

Em `docker-compose.yml`, substitua o serviço `traefik` inteiro por:

```yaml
  # Gera a CA de desenvolvimento do RPC e o certificado do servidor. One-shot,
  # como o mosquitto-init: roda antes do Traefik, que monta o resultado.
  traefik-init:
    image: alpine:3.19
    container_name: sinalacs-traefik-init
    environment:
      # SANs adicionais para validar em aparelho físico na LAN:
      #   RPC_CERT_SAN_EXTRA='IP:192.168.0.10' docker compose up
      #
      # ATENÇÃO, medido: com a stack JÁ DE PÉ, mudar só esta variável regera a
      # folha (o `traefik-init` é recriado) mas **não** recria o `traefik`, que
      # continua servindo a folha antiga — o fingerprint só muda depois de
      # `docker compose restart traefik`.
      #
      # E a consequência mais afiada, que o mesmo mecanismo produz: se o
      # `traefik-init` **regerar a CA** (arquivo ausente ou expirado), o Traefik segue
      # servindo a folha antiga enquanto o `runtime/certs/ca.crt` novo já está no
      # disco — e aí `curl --cacert …` falha com "unable to get local issuer
      # certificate" até um `docker compose restart traefik`. O Compose não recria o dependente
      # quando só o `environment` do one-shot muda. Subir do zero funciona,
      # porque o `depends_on` garante a ordem. Sem o restart, o teste em
      # aparelho físico falha na validação de hostname e a mensagem não diz por quê.
      RPC_CERT_SAN_EXTRA: ${RPC_CERT_SAN_EXTRA:-}
    volumes:
      - ./infra/docker/traefik/init.sh:/init.sh:ro
      - ./infra/docker/traefik/runtime:/certs
    entrypoint: ["/bin/sh", "-c", "apk add --no-cache openssl && sh /init.sh"]

  traefik:
    # v2.11 e nao v2.10: o provider Docker do v2.10 nao conecta neste Docker
    # ("client version 1.24 is too old. Minimum supported API version is 1.40"),
    # nenhum router de label nasce e o :443 devolve 404 do Traefik. Medido: v2.10
    # nao; v2.10 + DOCKER_API_VERSION=1.40 tambem nao (o cliente do v2.10 nao le a
    # variavel); v2.11 SIM; v3.5 nao. Sem flag de versao de API no v2.10 (--help
    # conferido). O sintoma e o mesmo que o Step 4 manda nao confundir com "o Host
    # nao casou", e o TLS ja funcionava: o que faltava era a rota.
    #
    # E NAO suba para o v3: o v3.5.6 e MAIS NOVO que o 2.11.57 e falha identico, com o
    # mesmo pin de 1.24 (medido no socket: /version responde ApiVersion 1.56,
    # MinAPIVersion 1.40, e /v1.24/version responde o erro). Nenhum Traefik v3 roda
    # neste host, e o v2.11 e o ULTIMO minor do v2 — nao ha para onde subir sem trocar
    # o provider Docker pelo de arquivo.
    image: traefik:v2.11
    container_name: sinalacs-traefik
    depends_on:
      traefik-init:
        condition: service_completed_successfully
    command:
      - --api.insecure=true
      - --providers.docker=true
      # O backend é roteado por label explícita (abaixo), não por exposição
      # automática: `exposedByDefault=false` impede que um serviço novo
      # publicado por engano ganhe uma rota pública sozinho.
      - --providers.docker.exposedByDefault=false
      - --providers.file.directory=/etc/traefik/dynamic
      - --entrypoints.web.address=:80
      - --entrypoints.websecure.address=:443
    ports:
      - "80:80"
      # Só o 443 chega ao RPC. O :80 continua declarado mas sem router nenhum
      # apontando para o backend — ver a remoção de 8080 no serviço abaixo.
      - "443:443"
      - "8081:8080"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./infra/docker/traefik/dynamic:/etc/traefik/dynamic:ro
      - ./infra/docker/traefik/runtime/certs:/certs:ro
```

- [ ] **Step 2: Rotear o backend e remover a porta em texto claro**

No serviço `serverpod`, **remova** o bloco `ports` inteiro:

```yaml
    ports:
      - "8080:8080"
```

e acrescente `labels` com o router:

```yaml
    # O RPC só é alcançável por HTTPS em :443. A publicação de 8080 foi
    # REMOVIDA de propósito: enquanto ela existisse, o TLS seria decorativo —
    # RNF04 pede TLS em todas as comunicações, e um caminho em texto claro ao
    # lado do cifrado é o caminho que alguém usa.
    labels:
      - traefik.enable=true
      - traefik.http.routers.sinalacs.rule=Host(`10.0.2.2`) || Host(`localhost`) || Host(`sinalacs.localhost`)
      - traefik.http.routers.sinalacs.entrypoints=websecure
      - traefik.http.routers.sinalacs.tls=true
      - traefik.http.services.sinalacs.loadbalancer.server.port=8080
```

O `loadbalancer.server.port=8080` é a porta **interna** do container, que continua sendo 8080 — o que muda é não haver mais publicação no host.

**Atenção ao `Host(...)`:** o emulador envia `Host: 10.0.2.2`; as ferramentas na máquina enviam `Host: localhost`. Se você validar por outro endereço (IP da LAN), acrescente-o à regra — uma regra sem casamento devolve 404 do Traefik, e a mensagem não diz que o problema é o `Host`.

## Task 3: `sync_dev_ca.sh` copia também a CA do RPC

**Files:**
- Modify: `scripts/dev/sync_dev_ca.sh`

**Interfaces:**
- Consumes: `infra/docker/traefik/runtime/certs/ca.crt` (Task 1).
- Produces: `apps/acs/assets/certs/dev_rpc_ca.crt` e `apps/patient/assets/certs/dev_rpc_ca.crt`.

O script de hoje copia só a CA do Mosquitto para o app ACS. Ele passa a copiar as duas, para os dois apps — o do paciente nunca teve CA porque nunca falou TLS com nada.

- [ ] **Step 1: Reescrever o script**

```bash
#!/usr/bin/env bash
#
# Copia as CAs de desenvolvimento para os assets dos apps.
#
# São DUAS CAs, e de propósito:
#   * a do Mosquitto assina o certificado do broker, e o app ACS a usa para o
#     MQTT em 8883;
#   * a do RPC assina o certificado que o Traefik apresenta em 443, e os dois
#     apps a usam para o HTTPS do backend (RNF04).
#
# `SecurityContext.setTrustedCertificatesBytes` lê bytes (e não um caminho, que
# não existiria dentro do APK), então as CAs entram como asset Flutter.
#
# As duas NUNCA são versionadas: `infra/docker/*/runtime/` e `apps/*/assets/certs/`
# estão no `.gitignore`.
#
# ATENÇÃO à distinção, que o `init.sh` do RPC mediu: as CAs são **PRESERVADAS** entre
# subidas e só as folhas são regeradas (ver a Task 1). Então esta cópia continua válida
# enquanto a CA não expirar — a folha muda a cada subida, mas o app confia na CA, não
# na folha. O broker segue o mesmo arranjo.
#
# Rode este script sempre que subir a stack pela primeira vez ou depois de apagar um
# `runtime/` — e, desde a Task 3, antes de qualquer `flutter build` do app do paciente:
# declarar `assets/certs/` no pubspec NÃO faz o build falhar se o diretório não existir
# (medido: o build sai 0 e empacota um APK SEM certificado), mas faz o `flutter analyze`
# falhar com `asset_directory_does_not_exist`. A falha do build é silenciosa, que é pior.
set -euo pipefail

repo_root="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"

copy_ca() {
  local source_ca="$1"
  local target_dir="$2"
  local target_ca="$3"
  local label="$4"

  if [[ ! -f "$source_ca" ]]; then
    echo "erro: $source_ca não existe." >&2
    echo "Suba a stack primeiro (docker compose up) para que as CAs sejam geradas." >&2
    exit 1
  fi

  if ! openssl x509 -in "$source_ca" -noout -checkend 0 >/dev/null 2>&1; then
    echo "erro: a CA em $source_ca está expirada." >&2
    echo "Apague o runtime correspondente e suba a stack de novo." >&2
    exit 1
  fi

  mkdir -p "$target_dir"
  cp "$source_ca" "$target_ca"
  echo "CA ($label) copiada para $target_ca"
  openssl x509 -in "$target_ca" -noout -subject -dates
}

for app in acs patient; do
  copy_ca \
    "$repo_root/infra/docker/mosquitto/runtime/certs/ca.crt" \
    "$repo_root/apps/$app/assets/certs" \
    "$repo_root/apps/$app/assets/certs/dev_ca.crt" \
    "MQTT"
  copy_ca \
    "$repo_root/infra/docker/traefik/runtime/certs/ca.crt" \
    "$repo_root/apps/$app/assets/certs" \
    "$repo_root/apps/$app/assets/certs/dev_rpc_ca.crt" \
    "RPC"
done
```

O app do paciente passa a ter `assets/certs/` — confirme que `apps/patient/pubspec.yaml` declara a pasta em `flutter: assets:`. Se ele ainda não tiver bloco `assets`, acrescente:

```yaml

  assets:
    - assets/certs/
```
